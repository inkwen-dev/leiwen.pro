## 方案选择决策树

```
开始
  │
  ├─ 项目类型？
  │   ├─ Next.js App Router → 选择 next-intl ⭐
  │   ├─ Next.js Pages Router → 选择 next-i18next
  │   └─ 纯 React → 选择 react-i18next
  │
  ├─ 内容类型？
  │   ├─ 静态内容 → JSON 文件存储 ⭐
  │   ├─ 数据库内容 → 翻译表方案 ⭐
  │   └─ Blog 内容 → Markdown + 多语言目录 ⭐
  │
  ├─ 团队规模？
  │   ├─ 个人/小团队 → 简单方案（JSON/Markdown）
  │   └─ 大团队 → CMS 方案

  └─ 语言数量？
      ├─ 2-3种语言 → 多语言字段方案
      └─ 3+种语言 → 翻译表方案 ⭐
```

## 针对我们项目的推荐方案

### 当前状态

- **框架**：Next.js App Router
- **内容类型**：静态内容（项目列表）
- **语言需求**：英文 + 中文

### 推荐方案：next-intl + JSON 文件 ⭐⭐⭐⭐⭐

#### 理由

1. ✅ **技术栈匹配**：专为 Next.js App Router 设计
2. ✅ **简单易用**：配置简单，学习曲线低
3. ✅ **性能优秀**：构建时处理，运行时性能好
4. ✅ **易于维护**：JSON 文件易于编辑和管理
5. ✅ **SEO 友好**：支持路由国际化
6. ✅ **类型安全**：TypeScript 支持好

#### 实施步骤

1. **安装依赖**
   ```bash
   npm install next-intl
   ```

2. **创建文件结构**
   ```
   messages/
     en.json
     zh.json
   app/
     [locale]/
       layout.tsx
       page.tsx
   i18n.ts
   middleware.ts
   ```

3. **配置国际化**
   - 创建 `i18n.ts`
   - 创建 `middleware.ts`
   - 更新 `next.config.ts`

4. **迁移内容**
   - 提取硬编码文本到 JSON 文件
   - 更新组件使用 `useTranslations()`

5. **测试验证**
   - 测试所有语言版本
   - 验证路由和 SEO

**预计工作量：** 1-2 天

## 通用最佳实践

### 1. URL 结构

#### ✅ 推荐：语言前缀路径

```
/en/about
/zh/about
/en/blog/post-1
/zh/blog/post-1
```

**优点：**
- ✅ SEO 友好
- ✅ 清晰的 URL 结构
- ✅ 易于识别语言

#### ❌ 不推荐：查询参数

```
/about?lang=en
/about?lang=zh
```

**缺点：**
- ❌ SEO 不友好
- ❌ 需要 JavaScript 处理
- ❌ 不利于分享

### 2. 语言检测

#### 自动检测

```typescript
// middleware.ts
export default createMiddleware({
  locales: ['en', 'zh'],
  defaultLocale: 'en',
  localeDetection: true // 自动检测浏览器语言
});
```

#### 手动切换

```typescript
// components/LanguageSwitcher.tsx
'use client';

import { useLocale } from 'next-intl';
import { useRouter, usePathname } from 'next/navigation';

export default function LanguageSwitcher() {
  const locale = useLocale();
  const router = useRouter();
  const pathname = usePathname();

  const switchLocale = (newLocale: string) => {
    const newPath = pathname.replace(`/${locale}`, `/${newLocale}`);
    router.push(newPath);
  };

  return (
    <select value={locale} onChange={(e) => switchLocale(e.target.value)}>
      <option value="en">English</option>
      <option value="zh">中文</option>
    </select>
  );
}
```

#### 记住用户选择

```typescript
// 使用 Cookie 或 LocalStorage
import Cookies from 'js-cookie';

const switchLocale = (newLocale: string) => {
  Cookies.set('locale', newLocale, { expires: 365 });
  // ... 切换逻辑
};
```

### 1. hreflang 标签

```typescript

export async function generateMetadata({
  params: { locale }
}: {
  params: { locale: string };

  return {

        'en': '/en',
        'zh': '/zh',

      }
    }
  };
```

### 2. 正确的 lang 属性

```typescript

export default function LocaleLayout({
  children,
  params: { locale }
}: {
  children: React.ReactNode;
  params: { locale: string };
}) {
  return (
    <html lang={locale}>
      <body>{children}</body>
    </html>
  );
}
```

## 维护建议

### 1. 使用 TypeScript 类型定义

```typescript
// types/i18n.d.ts
import 'next-intl';

declare module 'next-intl' {
  interface Messages {
    common: {
      save: string;
      cancel: string;
    };
    projects: {
      title: string;
    };
  }
}
```

### 2. 统一的翻译键命名规范

- 使用小写字母和点号分隔
- 按功能模块组织
- 保持一致性

### 3. 定期检查翻译完整性

```typescript
// scripts/check-translations.ts
import enMessages from '../messages/en.json';
import zhMessages from '../messages/zh.json';

function checkTranslations(en: any, zh: any, path = '') {
  const enKeys = Object.keys(en);
  const zhKeys = Object.keys(zh);
  
  const missingInZh = enKeys.filter(key => !zhKeys.includes(key));
  const missingInEn = zhKeys.filter(key => !enKeys.includes(key));
  
  if (missingInZh.length > 0) {
    console.warn(`Missing in zh${path}:`, missingInZh);
  }
  if (missingInEn.length > 0) {
    console.warn(`Missing in en${path}:`, missingInEn);
  }
  
  // 递归检查嵌套对象
  enKeys.forEach(key => {
    if (typeof en[key] === 'object' && typeof zh[key] === 'object') {
      checkTranslations(en[key], zh[key], `${path}.${key}`);
    }
  });
}

checkTranslations(enMessages, zhMessages);
```

- **Phrase**：翻译管理系统
- **Lokalise**：本地化平台

## 与其他技术栈对比

### Next.js/React vs Java 多语言方案

#### Java 框架多语言方案

**常见方案：**
1. **Spring Boot + MessageSource**
   ```properties
   # messages_en.properties
   welcome.message=Welcome
   
   # messages_zh.properties
   welcome.message=欢迎
   ```

2. **Java ResourceBundle**
   ```java
   ResourceBundle bundle = ResourceBundle.getBundle("messages", locale);
   String message = bundle.getString("welcome.message");
   ```

#### 对比分析

| 特性 | Next.js/React | Java 框架 |
|------|---------------|-----------|
| **运行环境** | 浏览器 + Node.js | JVM |
| **渲染方式** | CSR/SSR/SSG | 主要是 SSR |
| **文件格式** | JSON | Properties |
| **类型安全** | TypeScript 支持好 | 需要手动处理 |
| **性能** | 客户端缓存好 | 服务端处理 |
| **SEO** | SSR/SSG 支持好 | 服务端渲染天然支持 |
| **学习曲线** | 中等 | 中等 |
| **开发效率** | 高 | 中等 |

#### 关键区别

1. **运行环境不同**
   - Next.js：浏览器和 Node.js
   - Java：JVM

2. **渲染方式**
   - Next.js：支持 CSR/SSR/SSG，灵活
   - Java：主要是服务端渲染

3. **文件格式**
   - Next.js：JSON（结构化数据）
   - Java：Properties（键值对）

4. **性能考虑**
   - Next.js：可以客户端缓存，减少服务器压力
   - Java：需要服务端处理，服务器压力较大

5. **开发体验**
   - Next.js：TypeScript 支持好，开发效率高
   - Java：需要编译，开发周期较长

## 常见问题解答

### Q1: 如何处理动态内容的多语言？

**答：** 使用数据库翻译表方案，存储动态内容的多语言版本。

### Q2: 如何添加新语言？

**答：**
1. 在 `i18n.ts` 中添加语言代码
2. 创建新的翻译文件（如 `messages/ja.json`）
3. 更新语言切换组件

### Q3: 如何处理复数形式？

**答：** 使用 next-intl 的复数支持：
```json
{
  "items": "{count, plural, =0 {No items} one {# item} other {# items}}"
}
```

### Q4: 如何处理日期和数字格式化？

**答：** 使用 next-intl 的格式化功能：
```typescript
const format = useFormatter();
const date = format.dateTime(new Date());
const number = format.number(1234.56);
```

### Q5: 如何测试多语言功能？

**答：**
1. 手动测试所有语言版本
2. 使用自动化测试工具
3. 检查翻译完整性脚本

### Q6: 如何处理 RTL（从右到左）语言？

**答：** next-intl 支持 RTL，在配置中设置：
```typescript
export const locales = [
  { code: 'en', dir: 'ltr' },
  { code: 'ar', dir: 'rtl' }
];
```
